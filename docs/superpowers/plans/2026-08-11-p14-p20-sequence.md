## Dependency and lifecycle rule

P14 through P20 execute sequentially because each consumes a contract produced
by the preceding phase. Inside an individual phase, its packet's non-overlapping
work packages may run in parallel after their shared interfaces are locked.

The open `docs/execution/DEFERRED_END_TO_END_QUALIFICATION.md` ledger permits
this implementation sequence but caps every inheriting phase at `IMPLEMENTED`.
No plan marks a physical, two-hour, provider, reader, security, consent, or
owner-isolation gate as passed without direct evidence. P21 does not start from
this sequence; the P20 conversation stops after its handoff.

## Recommended execution method

Use `superpowers:subagent-driven-development` inside each phase where exclusive
file ownership permits parallel packages. The main agent performs preflight,
interface integration, narrow reruns, the complete phase gate, evidence/state
updates, and final handoff. Start the next phase only in a new conversation.

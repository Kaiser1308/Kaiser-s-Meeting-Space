## Environment root-cause investigation

`pnpm-workspace.yaml` deliberately resolves `storeDir: ../../../../../pnpm-store`,
which maps to `C:\pnpm-store` from this repository. Both the project pnpm 10.14.0
and the bundled pnpm 11.16.0 fail in `StoreIndex.openDatabase()` with
`ERR_SQLITE_ERROR: unable to open database file` before a test process starts.
The workspace-local `.pnpm-store` is a distinct store, but a command-line
override reaches the package-manager signature/dependency health check and its
child install still opens the configured external store. No store deletion,
re-link, package installation, or configuration rewrite was attempted because
the working tree contains extensive unrelated active changes and those actions
would mutate shared dependency state.

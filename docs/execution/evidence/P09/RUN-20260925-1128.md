## Follow-up: direct app launch crash (2026-09-25, UTC+7)

- To bypass the blocked Maestro driver without changing device security settings, launched the installed app directly with `adb shell am start -W -n com.anonymous.kaisermeetingspace/.MainActivity`.
- Android started `MainActivity`, then reported `APP CRASH (NATIVE)`, status `6`. The native-crash report identified an uncaught React Native JavaScript exception: `Cannot make a deep link into a standalone app with no custom scheme defined`. The call chain was `ExpoLinking.createURL` → `createAuthRedirectUri` during app startup; Hermes then terminated the process with `SIGABRT`.
- `pnpm exec expo config --json` resolves the workspace-root scheme as empty, while the same command from `apps/mobile/` resolves `scheme=kms`. Root `app.json` defines the Android package only; `apps/mobile/app.json` defines the existing `kms` scheme. The root Android `MainActivity` manifest has no `VIEW` filter for `kms`; the generated `apps/mobile/android` manifest does.
- This reproduces the app-start blocker before the permission screen. No change to the scheme, OAuth provider, permission state, or app data was made. `RECORD_AUDIO` remains denied, and no audio capture occurred.
- Proposed fix is pending owner approval: make the workspace-root Expo config and root Android intent filter match the already established `kms://oauth/callback` contract, then add a regression test against the resolved root config and manifest.
